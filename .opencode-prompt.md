## Feature 18: Guest RSVP (by name only, no account)

AC:
- Guest RSVP form: name field + response buttons (Coming/Maybe/Not Coming)
- No email, password, or account creation required
- Response confirmed instantly with optimistic update
- Browser cookie remembers the guest so they can return and change their response
- If the cookie is cleared/missing, show the name field again but allow re-entering
- Guest names appear alongside registered user names in the attendee list

## Implementation plan

1. **DB: add a `guests` table** — id, name, event_id, status (in/out/maybe), token (cookie), timestamps. Also a unique constraint on (event_id, token) so a guest can only have one RSVP per event.
2. **Server action: `setGuestRsvp`** — accepts eventId, name, status, guestToken. Inserts or updates. Returns the guest token in a cookie.
3. **Make event detail page public** — remove the `if (!session) redirect("/login")` guard. Show event details for everyone. If authenticated, show normal RSVP buttons. If unauthenticated, show the guest RSVP form (name input + buttons).
4. **Guest RSVP component** — client component that checks for guestToken cookie, shows name field if missing, RSVP buttons if present. Uses `setGuestRsvp` server action.
5. **RSVP counts** — query both `rsvps` and `guests` tables to show combined counts per status.

## Drizzle schema note

SQLite `text()` enums are TypeScript-only. Adding a new value does NOT need a migration.

## Common pitfalls

- Unused imports (e.g. `eq`) will fail ESLint on build
- Always use `COREPACK_HOME=/tmp/corepack` prefix for pnpm
- Don't add migration files unless actually needed (SQLite schema changes don't always need one)
